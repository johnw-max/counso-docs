# 工程团队场景

工程团队可以用智能体检索技术文档、解释代码或数据结构、整理故障记录并准备便于复核的草稿。具体结果取决于工作区连接的代码库、工具和运行环境。

## 代码和系统问题

提供相关代码库或文档范围、版本和错误上下文。要求智能体引用文件或章节，并区分直接观察到的内容和推断。生成的代码或命令只应视为建议，使用前需在合适的环境中检查和测试。

## 故障总结

提供获准使用的事件时间线、日志或笔记，并说明目标读者。要求分别整理影响、已确认时间线、促成因素、待查问题和跟进事项。不要让它编造根因，也不要在报告中加入凭证或个人数据。

## 技术文档助手

智能体可以根据获准的运行手册、接口参考和内部指南回答重复问题。说明涉及的服务或版本，并要求引用源文件。流程变化后，应指定负责人维护底层文档。

## 请求示例

```text
请检查这份服务 X 故障记录。区分已确认事件和假设，逐项注明依据，并提出后续检查建议。不要下根因结论，也不要修改代码、告警或生产系统。
```

代码库写入、工单更新、部署和事故通知都需要单独启用的工具，并遵循工程团队的正常审核流程。
