# 团队协作场景

共享对话或 Pod 可以把讨论、依据、决定和跟进工作放在一起。应根据受众选择协作空间；除非所有成员都应查看内部讨论，否则不要把内部内容移入客户可见区域。

## 邀请合适的人参与

在界面支持时，使用提及选择器邀请同事或智能体。说明需要对方做什么、何时完成。提及可能会通知对方或进入邀请流程，但不一定会授予对话所用数据源的访问权限。

## 在 Pod 中共享工作

如果团队需要持续保留历史、文件和任务，可以使用 Pod。说明用途，只添加目标成员，并在对话中记录决定。后续事项应转为任务，写明负责人、预期结果和下一步。

## 需要人工判断时升级

可以在智能体指令中要求它标出需要专业人员处理的情况，例如依据不清、政策冲突或客户承诺。智能体应解释升级原因和缺失信息，由负责人决定下一步。

## 跟进待办事项

如界面提供未读或指派视图，可用来查看待处理内容，并及时更新任务负责人和状态。通知取决于每位用户的设置；没有收到通知，并不能证明没有待办事项。

## 指令示例

```text
如果缺少来源、两项政策冲突，或所请求的操作需要审批，请暂停并说明问题、依据以及应由谁复核。不要代替负责人作决定，也不要发送外部消息。
```

分享对话前，确认目标受众及其对所有关联数据源的访问权限。
