# 设计可落地的使用场景

从一项具体工作开始定义场景：谁遇到什么问题、目前如何处理、希望智能体交付什么，以及由谁复核结果。不要先堆叠功能和工具。

## 选择适合试用的工作

优先考虑重复发生、资料来源清楚、输出容易核对且出错时能及时发现的任务。例如汇总文档、依据政策回答内部问题、整理客户反馈、准备对账异常清单。涉及付款、账务过账、法律判断或对外承诺的步骤，必须由人复核。

## 写清场景说明

每个候选场景记录以下信息：

- 用户和流程负责人；
- 输入资料、业务对象和时间范围；
- 期望输出，以及不能推断或执行的事项；
- 来源权限、复核人和异常升级方式；
- 当前耗时、质量问题和成功标准。

## 小范围试跑

用两三个有代表性的样例测试正常、资料缺失和信息冲突的情况。记录错误类型和人工修改时间，再调整指令或来源范围。流程稳定后，再扩大使用范围或增加工具。
