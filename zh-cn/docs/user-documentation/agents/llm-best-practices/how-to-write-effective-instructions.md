# 编写有效的智能体指令

指令说明智能体如何处理一类重复任务。可以把它写成给一位能力不错、但还不了解你们流程的同事的工作说明：语言直接，补充相关背景，并说清怎样的结果才有用。Sidekick 可以帮忙起草或修改，但保存前要逐项检查它的建议。

## 实用结构

按任务需要补充以下内容：

- **角色和目标：** 智能体在帮助谁、要完成什么。
- **流程：** 如果工作有固定顺序，写明需要遵循的步骤。
- **专业背景：** 智能体需要了解的政策、定义、受众或示例。
- **约束：** 使用哪些来源、不能擅自假设什么，以及证据缺失或不一致时如何处理。
- **输出：** 回答格式、详细程度和需要包含的字段。

例如，不要只写“复核这些发票”，还要说明复核期间和文件范围、需要比对的字段、如何报告差异，以及哪些结论需要由人确认。

## 让指令便于执行

使用具体句子，不要只堆搜索关键词。只加入会影响答案的背景；指令越长并不代表越好。示例可以展示偏好的格式，也可以区分合格答案和不合格答案。复杂流程可以拆成清晰步骤，但不要要求模型公开隐藏推理过程。

## 测试和修订

用几种有代表性的请求测试，包括信息不完整的情况。检查智能体是否使用了预期来源、遵循输出格式，并在必要时追问。若结果不理想，每次修改一部分指令后再测试。始终围绕智能体的目标使用者和任务来写。
