# 设置 Webhook 触发器的频率限制

Webhook 触发器可以限制滚动 24 小时内接受并启动智能体运行的事件数量，避免繁忙的数据源产生超出预期的运行。当前限制以及可修改的上限会显示在触发器设置中。

## 设置单个触发器的上限

在 Agent Builder 中打开 Webhook 触发器，检查 **Rate limits（速率限制）** 字段。测试新来源时先保留默认值；只有正常事件量确实需要时再提高上限。定时触发器由时间表本身控制频率，不受 Webhook 事件上限约束。

触发器频率上限与 credits 来源互相独立。更改由谁承担运行资源，不会提高允许的请求速率。credits 来源见[Credits 使用](../credits-usage.md)。

## 工作区级限制

根据方案和配置，工作区还可能设有汇总上限或资源限制。请查看当前 Usage 或触发器设置中适用的上限，不要认为提高单个触发器的限制就能解除工作区级约束。

## 达到限制时

触发器可能将请求标记为超出速率限制并拒绝处理。请求可能直接丢弃而不是排队，因此滚动窗口解除后也不一定补跑。请检查触发器运行详情，确认工作区中的实际行为。若频繁达到上限，可用 payload 筛选减少不必要事件，或在允许时调整单个触发器的上限。
