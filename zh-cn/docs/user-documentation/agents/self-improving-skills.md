# 查看 Skill 改进建议

启用 **Self-improving Skills（自我改进 Skills）** 后，工作区可以分析使用过 Skill 的对话，并为 Skill 提出修改建议。信号可能包括明确反馈、用户纠正智能体回答、需要某项能力却未使用，或对话偏离目标。建议用于帮助 Skill 编辑者改进可重复使用的指导；未经编辑者批准，不会直接修改 Skill。

## 审核建议

1. 在 Skill Builder 中打开 Skill，并查看侧边栏里的建议。
2. 阅读拟议修改，确认它会改变哪种行为。
3. 选择 **Approve（批准）** 应用修改，或选择 **Decline（拒绝）** 忽略建议。
4. 批准后，用有代表性的任务测试更新后的 Skill，并在历史记录中查看新版本。

建议可能修改指令，或调整 Skill 使用的工具。接受前应判断修改是否适合 Skill 的使用者和访问范围。

## 控制功能

此功能为可选项。管理员可以在工作区设置中关闭；每个 Skill 也可能有自己的自我改进开关。关闭工作区功能后，不再分析对话或生成新建议；关闭单个 Skill 不会改变工作区级别的设置。

## 数据与处理方式

分析可能使用对话消息、工具调用、智能体回复、用户反馈，以及当前 Skill 的指令和工具配置；处理时会使用工作区已配置的模型服务提供方。启用前，请先核对工作区适用的数据处理、用户告知、访问和保留要求。建议和分析记录保存在工作区治理范围内。此功能是为工作区 Skill 提出修改建议，并非用这些对话训练通用模型。

## 处理模式与积分

分析按夜间计划执行。默认批处理模式会把任务交给模型服务商异步处理，服务商完成一批任务可能需要最多 24 小时，因此反馈后不一定马上出现建议。

批处理需要在服务商侧暂存请求和结果，不能默认认为交互调用的零数据保留安排也覆盖批处理。如果工作区提供批处理开关，管理员可关闭批处理而继续保留 Skill 改进，此时改用同步流式调用。流式调用是否符合零数据保留要求，仍取决于服务商和工作区协议。有严格要求时，请确认配置符合要求，或关闭自我改进。

分析会消耗工作区积分。具体费用查看 Usage 和当前工作区计价；流式与批处理的成本可能不同。

## 保留人工审核

建议可能从个别对话中过度归纳，也可能只是反映一次性的偏好。只有当修改表达了适用于目标使用者的可重复规则时，才应接受。异常结果仍需人工检查；可以通过 Skill 历史了解或撤回修改。
