# 工作区角色、群组和权限

工作区角色确定成员的基础职责；群组权限可以增加指定的管理能力。访问具体 Space、智能体或 Skill 则是另一层资源权限。排查某人能否执行操作时，这三层都要检查。

## 工作区角色

- **Admin（管理员）：** 管理工作区配置、成员和安全设置；部分治理控制项仅管理员可用。
- **Manager（经理）：** 在获得相应权限时，负责受委派的成员与日常管理工作，例如邀请成员或处理成员请求。Manager 默认不一定拥有账单和安全管理权限。
- **Member（成员）：** 根据授予的权限和具体资源的访问范围使用工作区内容。

当前可执行操作以工作区显示的角色和控制项为准。不要仅根据角色名称推断成员能访问所有 Space 或连接数据源。

## 群组和权限模式

工作区群组可以手动维护；配置目录同步后，也可以从身份提供商同步。通常通过群组授予权限，便于集中管理团队，而不必逐个编辑成员。成员属于多个群组时，可以获得这些群组授予的权限组合；某个群组的授权不会撤销从其他途径获得的权限。

治理权限可能设为 **Everyone（所有成员）**、指定的 **Groups（群组）** 或 **Admin only（仅管理员）**。只向能够完成该项工作的最小范围开放权限。如果要给单个人例外授权，可在工作区支持时使用管理得当的群组。

## 常见的委派权限

工作区可能提供创建或发布智能体与 Skills、查看审计记录或分析数据、管理账单或安全设置，以及发布或分享 Frame 等治理控制项。这些权限彼此独立：授予 Manager 发布智能体的权限，不一定同时开放账单或安全管理。

## 检查实际生效的权限

排查访问问题时，分别核对成员的工作区角色、群组成员身份和授权、目标资源的受众范围，以及数据源权限。一次只保存一项变更，再让受影响成员重试。如果界面中看不到所需控制项，请管理员确认工作区配置。
