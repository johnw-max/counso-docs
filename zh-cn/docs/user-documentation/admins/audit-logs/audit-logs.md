# 查看工作区审计日志

审计日志按时间记录工作区中的重要操作。启用这项功能后，Admin 默认可以访问；Manager 或 Member 需要获授查看和导出权限。

## 开始前

先明确调查目标，例如失败登录、智能体变更、成员变更、意外工具调用或目录同步事件。记下大致时间、发起者、资源和操作。如果管理区域中没有审计日志入口，请管理员确认功能是否已启用，并检查你的角色或被委派的权限；仅凭空白页面不能判断没有发生事件。

## 查找相关事件

1. 在管理区域中选择 **Audit Logs**（如果该控件可用）。
2. 先设定最小的有效时间范围。根据已知的发起者、资源、操作或标识符搜索，需要时再扩大范围。
3. 按类别筛选，例如智能体创建或运行、工具执行、触发器和 wake-up 变更、Space 权限、成员和角色变更、数据源授权、登录、OAuth、SSO 或目录同步，以及对话访问。
4. 打开事件并一并查看操作、时间、发起者、目标、上下文和元数据。发起者可能是用户或系统进程；智能体和工具事件的元数据可能会说明操作由用户发起还是由 AI 驱动。
5. 对比同一发起者和目标附近的事件，区分配置变更与随后发生的运行。

打开查看器本身也会记录为 `audit_log.viewed`。整理调查记录时应包含这条事件。

## 导出和持续传送日志

如果查看器提供 CSV 导出，导出筛选结果后核对时间范围、行数和代表性事件。将筛选条件和导出时间与文件一起保存，方便其他管理员复现查询范围。

如果工作区的审计日志设置提供持续日志传送，管理员可以在设置中配置支持的目标，例如 Datadog、Splunk、AWS S3、GCP GCS 或自定义 HTTPS 端点。按照工作区中显示的目标配置操作，并在接收端确认日志已收到。是否提供持续传送及具体目标取决于工作区配置；该功能需要管理员启用。

## 常见问题

### 为什么打不开审计日志？

请工作区管理员确认已启用该功能，并检查你的 Admin 角色或被委派的查看/导出权限。

### 发起者字段会说明是否使用了 AI 吗？

对于智能体和工具事件，要同时查看发起者和事件元数据。发起用户仍可能显示为发起者，而元数据会标识操作由 AI 驱动。

### 为什么打开查看器后多了一条事件？

查看器访问本身会记录为 `audit_log.viewed`，所以调查开始时间附近出现这条事件是预期行为。
