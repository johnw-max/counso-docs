# Counso route mapping

`routes.json` is the machine readable URL ledger for this delivery. It is
generated from the packaged acquisition manifest, the current read-only
crosscheck and content manifest, the current sheet snapshot, and the 31 URL
application input. The generator performs no network access and does not
modify cloud documents or the acquired source.

Each `routes[]` row is one URL alias or source entry. `originalUrl` is
the old Dust URL, including its path and any incoming fragment. The 31
application rows also have `deploymentUrl`, the corresponding Counso host
that the compatibility route should serve. `canonicalUrl`, `sourceRecordId`,
`sourceFile`, `archiveFile`, and `sourceHash` identify the immutable acquired
source bytes. `sourceFile` points to the byte-checked Markdown under
`reference/markdown`; `archiveFile` points to the original body.
`sourceRepositoryUrl` and `snapshotDownloadUrl`, when present, retain the
fixed peer repository and raw snapshot links from `reference/url-to-original`.

`targetTopicId` and `targetSection` are the primary Counso destination.
`target.en` and `target.zh-cn` give the actual package file and public URL for
each language. A target may include `related` destinations when one old
article was intentionally split across topics, such as `/docs/data` and
`/docs/skills`.

The package publication policy in `content/release-policy.json` is applied
before the site consumes a target. All `developers/*` topics and the five
listed developer/API legacy paths are held because Counso has no public API in
this release. Those rows use `status: "excluded_api_not_public"`,
`published: false`, and a null `targetTopicId`; `heldTarget` retains the
package relative authored file, URL, section alias, and target hash for audit
without exposing it as a deployable route. No API placeholder page is
generated by this mapping.

Every target section uses this contract:

```json
{"alias":"ashby","anchor":"ashby","anchorStrategy":"stable_alias"}
```

The site build must inject the `anchor` alias into the corresponding heading
in both locale pages. This keeps legacy fragments stable without claiming
that an English slug is automatically the same heading id in Chinese. The
provider tool entries therefore point to explicit aliases such as `ashby`,
`freshservice`, `slack-tool-personal-actions`, and `snowflake-tool`.

The status is a routing decision, not a product acceptance claim:

- `legacy_alias_to_topic` and `legacy_alias_to_index` are serviceable old
  paths and should render or redirect to the authored Counso page.
- `mapped_to_counso_draft` and
  `mapped_to_counso_draft_needs_product_verification` identify source records
  that have a reviewed Counso rewrite. The latter records are not a build
  blocker; they carry the remaining product verification note for the owning
  team.
- `mapped_partial_upstream_claims_excluded` identifies a scoped rewrite where
  upstream commercial, privacy, support, or retention claims were removed.
- `excluded_api_not_public` identifies developer/API destinations that remain
  traceable but are intentionally withheld from publication.
- `archive_only_*` rows remain traceable source material and must not be
  presented as Counso content. Their `reason` is the specific disposition,
  including private API, unverified API contract, no exact source match, or
  upstream-only claims.

The application list is intentionally read from
`inputs/application-legacy-urls.txt`; the generator validates that it has 31
unique `docs.counso.ai` entries. Rebuild from the package root with:

```sh
python3 mapping/build_routes.py
```

The summary in `routes.json` asserts that all 356 manifest page records have
at least one manifest route, all 80 reviewed crosscheck ids are attached
(some share an existing manifest route), all 31 application entries are
present, and the application split is 26 published compatibility routes plus
5 API-held routes.
