# Design a useful use case

Define a use case around a specific piece of work: who needs what, how the work is done today, what the Agent should return, and who checks the result. Begin with the workflow, not a list of tools.

## Choose a good first task

Look for work that happens repeatedly, has clear sources, produces an output that can be checked, and allows a person to catch mistakes. Examples include summarising a document, answering a policy question, grouping customer feedback, or preparing a list of reconciliation exceptions. Keep human review for payments, ledger postings, legal conclusions, and external commitments.

## Write a short use-case brief

For each candidate, record the user and owner; input sources, entity, and period; expected output and prohibited actions; access boundary and reviewer; current effort and quality issues; and how success will be measured.

## Test with real examples

Use a few representative cases covering normal input, missing information, and conflicting sources. Record error types and human correction time. Adjust the instructions or source scope and repeat the test. Expand the audience or add tools only after the workflow is reliable.
