# Plan a team pilot

A useful pilot answers four questions: which problem comes first, who owns the work, which sources may be used, and how the team will judge the result. Set the duration and group size to fit the workflow instead of promising a fixed launch date or return in advance.

## Define the goal and boundaries

Start with repeated, low-risk work that is easy to verify, such as summarising a policy or listing items that need follow-up. Record the current process and its common delays or rework. Specify which sources the Agent may read, what it must not infer or change, who reviews its output, and when an exception must be escalated.

## Choose a small pilot group

Include a workflow owner, several regular users, and someone who can assess accuracy. Use representative examples, including a missing-information case, rather than testing only a polished demonstration.

## Review each cycle

Track completion time, material errors, missing evidence, human edits, and user feedback. When a result is poor, check the source scope and instructions before adding more tools. Change one factor, then repeat the same test.

## Expand when ready

Add another team, source, or automation only when the workflow is repeatable, the review owner is clear, and the access scope matches its audience. Recheck quality and exception handling after each expansion.
