# Example: support cases in a Pod

A support team can use a Restricted Pod to coordinate case review and keep approved troubleshooting material close at hand. Decide which roles may see customer details before adding any ticket content.

## Set it up

1. Create a Restricted Pod for the support group and assign an owner.
2. Add approved help articles, escalation rules, and known issues to **Files**.
3. Create a task for a case that needs investigation; include only the necessary reference and a clear next step.
4. Ask an Agent to summarise evidence, possible checks, and unresolved questions from sources it can access.

## Review a case

A support specialist verifies the diagnosis and checks that the proposed response matches the current guidance. The specialist edits and sends the response through the approved support system, then records the verified resolution in the appropriate knowledge source. The Pod can hold the collaboration history, but it should not become an uncontrolled second customer database.

Automatic ticket intake, assignment, or outgoing replies require dedicated enabled tools and a tested process. Keep a human review step for customer communications and sensitive changes.
