# Pod settings for workspace administrators

Workspace policies can affect who may create Pods, which visibility options are available, and whether members can add files. Administrators should review the settings offered in their own workspace; available controls and labels can differ.

## Review visibility choices

Decide whether members may create Open Pods or whether new Pods should be Restricted by default or by policy. Open access can expose conversations and files to a wider workspace audience. For customer, financial, personnel, or internal working material, choose the smallest appropriate membership boundary.

Changing a workspace policy may not retroactively change every existing Pod. Review existing Pods and their members separately after a policy change.

## Review file contribution rules

If the workspace offers a policy for manual Pod file additions, decide who may upload files or add linked material. A tighter rule can help keep sources centrally managed; a broader rule supports team collaboration but requires clear handling guidance.

Tell members what file types and sources are permitted, who owns the authoritative copy, and how corrections should be made. A Pod folder is for organisation, not for hiding a file from other members.

## Communicate and verify changes

Before a setting change, identify affected Pods and owners. After saving, open a representative Pod and confirm the actual creation or file controls match the intended policy. Do not assume that a hidden button or renamed setting is an access-control guarantee without checking who can still read existing content.
