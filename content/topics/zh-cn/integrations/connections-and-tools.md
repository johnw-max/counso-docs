# 连接与工具

## 选择接入方式

Counso 有两种让智能体使用外部信息的方式：

- **Connection（连接）**：把选定的服务商资料带入 Space，供搜索和检索使用。连接决定资料范围和刷新时间。
- **Tool（工具）**：让智能体调用服务商的具体操作，例如读取一个文件、查询一条记录或准备一次更新。工具使用分配给它的凭据和权限。

添加 Connection 不会自动添加该服务商的 Tool；添加 Tool 也不会让整个服务商的数据都可检索。例如 Google Drive Connection 负责同步和检索，原生 Google Drive Tool 负责精确文件和 Sheets 操作。凭据归属会影响责任人，请先阅读[个人与共享授权](./personal-and-shared.md#个人与共享授权)。

## 准备连接

1. 确认工作区管理员能够管理目标 Space 和服务商账号。
2. 决定资料应放入 Open Space 还是 Restricted Space。只选择完成任务所需的最小页面、文件夹、频道、数据库或项目范围。
3. 在 **Spaces** 中打开连接管理入口；当工作区提供该服务商时再选择它。
4. 完成服务商侧的授权或管理员设置，并记录连接使用的账号、资料范围和权限边界。
5. 等待首次刷新后，用一条已知且非敏感的资料请求检查检索结果，再回到服务商核对访问范围。

设置页面接受配置，只能说明配置被接受；它不能证明所有资料都已索引、每个用户都能看到相同内容，或智能体可以写回服务商。

## 网站和文件夹

网站来源是对公开资料的连接，供智能体检索；它不是实时浏览器会话。添加前定义允许的主机或路径、刷新行为和目标 Space。刷新后检查一页已知页面；除非服务商路径明确支持，不要把敏感或需要登录的网站放入其中。

使用文件夹把相关来源放在清楚的访问边界内。文件夹移动或成员变化，可能在服务商没有变化的情况下改变智能体能找到的资料，因此要一起检查文件夹、Space 和来源权限。

Dropbox、Front、Guru、HubSpot、Jira、Linear、Salesforce 或自动化服务的自定义导入属于资料来源路径。设置来源集合、导入负责人、刷新行为和目标 Space；导入来源不会自动授予实时写入能力。

### 设置网站抓取范围

1. 在 **Spaces → Connections** 添加网站来源，填入无需登录即可访问的起始 URL。
2. 需要站内关联页面时选择 **Follow all links within the domain**；只需要某个栏目时，从栏目 URL 开始并选择 **Only child pages of the provided URL**。
3. 用 **Page Limit** 限制页面数量；只收录起始页面时设为 1。用 **Depth of Search** 限制跟随链接的层数。最大可设值以当前表单为准。
4. 保存后等待抓取，检查一篇已知页面和一篇应被排除的页面，确认范围符合预期。
5. 外部页面更新后检查连接的刷新状态，再要求智能体使用最新资料。

抓取沿页面里实际存在的链接前进，不会猜测没有链接的地址。PDF 位于允许的抓取路径时可以纳入；跨域链接通常不会跟随，例如站内指向 Google Docs 的链接。需要登录、拒绝爬取或无法公开读取的网站不能按普通网站来源同步。

## 准备工具

1. 选择工具应当可用的 Space。
2. 在智能体的能力或工具配置中选择对应工具。
3. 根据谁应对服务商动作负责，选择 Personal 或 Shared 凭据。
4. 先对已知记录提出只读请求。对可写工具，在动作前要求明确确认。
5. 检查服务商回执，并用稳定 ID 重新读取同一对象；服务商记录才是最终依据。

## 理解刷新和访问范围

连接的刷新时间可能与服务商的实时工具不同。服务商刚更新的资料，可能先能被工具读取，稍后才会出现在同步来源中。移除用户的 Space 成员资格、改变服务商共享范围或更换凭据负责人后，也要在下一次刷新后做一次小范围访问检查。

请分开回答三个问题：

- **连接能找到资料吗？** 检查来源范围和刷新状态。
- **工具能对资料执行动作吗？** 检查工具凭据和服务商权限。
- **服务商接受动作了吗？** 检查服务商回执，并按稳定 ID重新读取对象。

## 常见连接问题

- **列表中没有服务商：** 检查工作区角色，以及该服务商是否在当前环境开放。
- **首次刷新为空：** 先检查 Space、来源范围、服务商共享权限和刷新状态，再考虑扩大访问范围。
- **工具看到的内容少于连接：** 对比凭据归属和服务商权限；两种路径的范围可能不同。
- **动作看似成功却找不到记录：** 使用服务商稳定 ID重新读取，不要只依赖智能体消息。
