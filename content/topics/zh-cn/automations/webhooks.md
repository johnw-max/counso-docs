# 使用 Webhook 触发助手

当外部服务发生新工单、代码变更或状态批准等事件时，可以使用 Webhook 启动助手。

## 开始前

请工作区管理员先启用所需的 Webhook 来源。确定事件字段、目标助手以及结果应进入的 Pod 或对话，并从来源取得示例载荷，以便选择最小的有效事件和字段。

## 设置 Webhook 触发器

1. 打开助手构建器，进入 **Triggers**。
2. 添加 Webhook 触发器，选择管理员已启用的 Webhook 来源。
3. 复制触发器界面生成的 Webhook 地址，并在来源服务中登记。按来源服务要求选择事件订阅，并使用界面和来源服务提供的值填写认证或签名设置。
4. 输入触发器名称，并说明什么事件应创建对话。
5. 如果界面提供，选择是否把载荷放入助手消息，并设置事件或过滤条件。
6. 在助手说明中指定目标 Pod。要求助手根据允许范围查找 Pod，并在创建任务时保留来源 ID。
7. 保存助手。从来源发送一条最小测试事件，检查触发器状态、已接收事件、创建的对话以及任务或文件，再启用更多事件。

## 完成后应看到什么

被接受的事件会启动配置好的助手运行，并在有权限的目标中产生结果。来源 ID 可以把运行与原始事件对应起来，并避免重复任务。

## 常见问题

### 为什么有效事件没有产生结果？

检查管理员启用的来源是否有效、来源订阅和认证是否匹配，以及事件名称、过滤条件、助手状态、目标访问权和可用额度。触及限制的事件不会自动排队。

### Webhook 能否写入 JSON 中任意命名的 Pod？

不能。助手必须根据当前用户访问权和自身配置解析允许的目标。载荷文字不是授权。

### 如何安全重放事件？

使用稳定的来源事件 ID，先搜索已有对话或任务，并要求助手更新已有项目，而不是创建新项目。
