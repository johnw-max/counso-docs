# Manage and share an Agent

Manage an Agent from its settings after you have reviewed its purpose and data scope. Keep the details clear so people can choose the right Agent and understand who maintains it.

## Update the settings

1. Open **Work** and go to **Agents**.
2. Select the Agent you maintain and open its settings.
3. Review the **Name** and **Description**. State the task, intended users, and important boundary in plain language.
4. In **Editors & Access**, use **Add editors** to include only people who should maintain the configuration.
5. Review the **Unpublished** dropdown. An unpublished Agent can be viewed and used only by its editors.
6. Add useful **Tags** so people can find the Agent, then save the changes when ready.

Before you make an Agent available more widely, check the access setting, data scope, instructions, and capabilities together. A clear name does not make a broad data scope safe.

## Share responsibly

Tell users what the Agent is for and what they should review. Start with a read-only task and non-sensitive material. If the Agent uses a connected service or can affect an external record, explain the confirmation step and where the final result must be checked.

After an access change, reopen the settings and ask an intended user to confirm what they can see. Remove editors and users who no longer need access. If an Agent disappears from a list, check its publication state and workspace permissions with an administrator.

For the configuration behind an Agent, read [Manage Agent data and access](./data-and-access.md#manage-agent-data-and-access) and [Preview and improve an Agent](./preview-and-improve.md#preview-and-improve-an-agent).
