# Create and configure a Skill

A Skill packages a repeatable way of working so that several agents can use the same procedure. Create one when the process has a clear purpose, inputs, decisions, and expected result.

## Before you begin

Write the procedure in plain language first. Identify the information it may use, the tools it needs, the people who may edit it, and the agents that should use it. Do not put unrelated procedures in one Skill.

## Create a Skill

1. In **Work**, open **Skills** and choose **Create skill**.
2. Give it a short name and a description that says when it should be used.
3. Write guidelines as an ordered procedure. Include required inputs, checks, stop conditions, and the shape of a successful result.
4. In the guidelines editor, use the capability or knowledge picker to add tools, other Skills, and approved source material.
5. Review the required Spaces and editors. Save the Skill while it is available only to editors.
6. Try it with safe sample material, then publish it to the smallest audience that needs it.

Keep instructions in the Skill when they should be shared and kept current. Keep a one-off request in the agent or conversation when it is specific to one run.

## What you should see afterward

The Skill appears in the Skills list with its name, description, editors, availability, and status. An agent can use it after it is explicitly added to that agent and the agent has access to every required resource. If you publish the Skill with **users and agents** availability, matching agents can discover it automatically; that still does not bypass the Skill's resource permissions.

## Common questions

### Why can I not create or edit a Skill?

Skill creation and editing require a builder or administrator role, or editor access to that Skill. Ask a workspace administrator to grant the appropriate role.

### Why did adding a tool add a data requirement?

Tools and attached knowledge can require access to a Space. Every user and agent that uses the Skill must be able to access all of its required resources.

### Should I copy a global Skill before changing it?

Customize it when you need workspace-specific guidance while preserving the original. Changes to the customized Skill do not change the global one.
