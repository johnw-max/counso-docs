# 管理 Skill 访问和版本

Skill 的访问有两个部分：谁能编辑或发现这个包，以及谁能访问它所需的全部工具、文件和 Space。

## 开始前

先确定受众和数据边界。新的流程先保持仅编辑者可用。只有样本运行清晰且安全后，才开放给工作区用户或助手自动发现。

## 设置访问并查看历史

1. 打开 **Work > Skills**，按名称搜索。
2. 打开 Skill 详情，检查编辑者、可用范围、所需资源和附件。
3. 只有需要维护流程的人才添加为编辑者。
4. 选择满足需求的最小范围：草稿使用 editors，直接使用使用 workspace users，需要自动发现时使用 users and agents。
5. 修改指南前，在 Guidelines 区域打开 **History**，按日期和作者比较相关版本。
6. 每次只保存一项完整改动，运行代表性检查，确认结果改善后再保留新版本。
7. Skill 不再维护时，先检查依赖它的助手，再从菜单归档。先移除或替换相关引用；归档是生命周期决定，不是隐藏错误流程的方法。

如果所需 Space 的访问发生变化，Skill 的可用受众也会随之变化。工作区管理员可以只读打开 Skill，再将自己加入编辑者后修改。

## 完成后应看到什么

Skills 列表会反映状态和可用范围。编辑者能确认何时改了什么；用户只有在具备 Skill 所需底层访问权时才能使用它。

## 常见问题

### 为什么看得到 Skill 却不能使用？

可能缺少所需 Space、工具或附件的访问权。请让编辑者检查 Skill 的依赖和你的成员关系。

### 为什么一次改动影响多个助手？

助手使用共享 Skill 包。保存后的更新会成为所有使用该 Skill 的助手共同采用的流程。

### 如何回退错误修改？

打开 History，对比最后一个可用版本，将其说明作为一次完整改动恢复。重新发布前先测试恢复后的流程。

### 归档 Skill 前应做什么？

在助手列表中查找使用它的对象，发布替代 Skill 或移除旧引用，并告诉编辑者维护中的流程在哪里。保留历史，方便审计和恢复。
