# 筛选、查看并导出审计日志

审计日志按时间记录工作区中的重要操作。工作区启用这项能力后，管理员或获授权的群组可以打开日志查看器。

## 开始前

先明确要回答的问题：失败登录、Agent 变更、成员变更、意外工具调用，还是目录同步事件。记下大致时间、发起者、资源和操作。如果看不到审计日志控制项，请管理员确认能力和访问权限是否已启用，不要把空白页面当作没有事件。

## 找到相关事件

1. 打开管理区域；在界面提供该控件时选择 Audit Logs。
2. 先设定最小的有效时间范围。已知发起者、资源、操作或标识符时使用全文搜索，需要时再扩大范围。
3. 按事件类别缩小结果。常用类别包括 Agent 创建或运行、工具执行、触发器和唤醒变更、空间权限、成员和角色变更、数据源授权、用户登录、OAuth、SSO 或目录同步，以及对话访问。
4. 打开结果，同时阅读操作、时间、发起者、目标、上下文和元数据。发起者可能是用户或系统进程。对于 Agent 和工具事件，元数据可以进一步说明操作由用户发起还是由 AI 驱动。
5. 对可疑事件查看同一发起者和目标附近的事件，把原始配置变更与它触发的后续运行区分开。

打开日志查看器本身会记录 `audit_log.viewed`。写调查记录时要把这条访问事件算进去。

## 导出审查范围

筛选结果正确后，在查看器提供 CSV 导出控件时使用它。打开导出文件，核对时间范围、行数和几条代表性事件，再交给审查人员。将筛选条件和导出时间与文件一起保存，方便另一位管理员复现范围。

## 重点事件类别

- **身份：**`user.login`、`user.login_failed`、`user.logout`、身份合并、域名验证、SSO 连接删除，以及 SCIM 用户或群组变更。
- **访问：** 成员邀请和撤销、成员关系创建、角色更新、空间权限变更和 Agent 范围变更。
- **Agent 活动：**`agent.created`、`agent.updated`、`agent.archived`、`agent.restored`、`agent.executed` 和 `tool.executed`。
- **自动化：** 触发器创建、启用、停用、删除或触发；唤醒创建、取消、过期或触发。
- **凭据和连接：** OAuth 授权或撤销、数据源重新授权、外部连接器凭据变更、MCP 连接变更，以及凭据失效。

## 常见问题

### 为什么打不开审计日志？

请工作区管理员确认审计日志已启用，并检查你的管理员角色或被委派的审计日志权限。

### 发起者字段会说明是否使用了 AI 吗？

对于 Agent 和工具事件，要同时检查事件元数据。发起者仍可能是启动操作的用户，而元数据会记录操作类型和发起身份。

### 为什么打开查看器后多了一条事件？

查看器访问本身会记录为 `audit_log.viewed`，所以调查开始时间附近出现这条事件是预期行为。
