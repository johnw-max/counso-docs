# 选择检索、提取或表格查询

查找一条政策、整理近期更新、从记录中提取字段和统计一张表，需要的处理方式不同。为智能体配置知识能力时，先写出希望得到的结果，再选择工作区提供的对应工具与来源。

## 按问题选择方法

| 要完成的工作 | 合适的方法 | 需要说明什么 |
| --- | --- | --- |
| 在许多文档中找到相关解释 | 检索知识来源 | 主题、期间、来源范围与所需引用 |
| 阅读一组确定的资料或近期更新 | 包含指定资料、读取文件 | 文件清单、时间范围与优先级 |
| 从非结构化记录中整理相同字段 | 提取数据 | 字段定义、缺失值规则、来源标识 |
| 计算数量、总额、分组或比例 | 表格查询或文件分析 | 数据表、字段、筛选、关联与单位 |

检索会挑选相关内容供回答使用，不能据此宣称读完全部来源。按最近时间纳入资料也不等于按问题相关性排序；资料过多时仍会受到可处理内容范围的限制。

## 配置一次有明确范围的知识任务

1. 打开可编辑的智能体，在 **Capabilities and knowledge** 中选择适合任务的知识能力。
2. 选择需要使用的来源。能选具体文件夹、页面、频道或表格时，先选择与任务直接相关的范围。
3. 写出明确的期间和输出要求。若所选能力提供标签或时间筛选，检查包含与排除条件是否符合资料实际标记。
4. 需要提取字段时，为每个字段给出含义和类型；需要计算时，说明每行含义、日期口径、货币单位和重复记录处理规则。
5. 预览一个答案已知的小样本。检查来源、字段或计算结果，再扩大范围。

## 从文字中提取数据

例如，把一周的支持记录整理为“请求编号、问题类别、是否解决、后续责任人、来源链接”。先规定类别，说明没有解决状态时应留空，而不是从语气猜测。若工具支持结构定义，可以使用 JSON Schema 描述字段和允许值；生成的结构也需要检查。

结果应能回到来源记录。出现同一个请求多次更新时，明确保留全部记录还是按请求编号合并，以及以哪个时间点的状态为准。输出符合结构，不代表信息已经完整或正确。

## 对表格进行查询

描述问题时给出具体口径，例如：“按月份汇总已完成订单的净额，排除取消订单，保留原始币种，并返回订单数量。”将多个表连接时，说明关联字段和一对一或一对多关系，避免重复行放大金额。

检查查询结果的行数、筛选条件、空值、日期边界和单位。若需要完整覆盖，核对实际使用的表和期间，不能只看回答中的总数。需要修改源表格时，使用相应操作工具，另外说明要修改的记录与字段。

## 排查不符合预期的结果

找不到内容时，先检查[来源选择](/zh-cn/knowledge/choose-sources/#选择-knowledge-来源)和[同步与操作工具的区别](/zh-cn/integrations/connections-and-tools/#连接与工具)。数值不正确时，确认任务是否误用了文本检索，以及表格是否存在重复行、字符串形式数字或混合币种。长时间段处理不完整时，按期间分批并核对每批范围；不要把缩小范围后的结果表述为全量结论。
