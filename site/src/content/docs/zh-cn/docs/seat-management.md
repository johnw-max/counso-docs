# 检查用量和席位访问

席位决定成员能否使用工作区中的相应功能；额度和支出限制决定运行还能消耗多少资源。两者需要分别检查。金额、包含额度、结算周期和取消规则以当前工作区的订阅页面和已签订的条款为准。

## 检查成员与席位

1. 用管理员身份打开 **Admin** 中的成员或席位区域。
2. 找到受影响成员，检查角色、席位类型、是否已接受邀请，以及访问是否有效。
3. 如果界面支持分配或回收席位，先确认需要使用的功能和费用影响，再保存调整。
4. 请该成员重新打开工作区，用一条普通请求确认访问恢复。

不要仅凭能打开智能体列表判断席位正常；发送消息和使用某些功能可能还有单独的限制。

## 检查额度和运行消耗

打开工作区提供的 Usage、Credits 或用量区域，确认当前统计周期、已用额度、剩余额度或支出上限。页面提供成员、智能体、模型或运行类型筛选时，用相同期间比较，先定位最主要的消耗来源。

对于定时任务和 Webhook，检查触发器使用的是个人额度还是工作区额度。能交互式发送消息，不代表触发器选择的额度池也有余额。API 或其他程序化运行也应检查所属工作区、运行身份和相应消耗记录。

减少不必要消耗时，优先停用重复的自动化、降低无用运行频率、缩小资料范围，再用同一请求比较可用模型的质量和消耗。不要为节省额度删掉任务必需的证据。

## 调整订阅或停止续订

只有具备账单管理权限的人员才应调整订阅。打开当前账单或订阅页面，检查生效时间、未结费用、席位变更和数据访问影响，再完成页面要求的确认。提交后重新打开订阅状态，核对是否已显示预期的变更及生效日期。

取消续订、移除成员和删除工作区是不同操作。取消后何时停止访问、已用费用如何结算、资料保留多久，应使用该工作区实际显示的规则；无法在页面确认时，先联系账单负责人。

## 区分个人问题与工作区问题

假设 Alice 能打开智能体却不能发送消息，而 Bob 可以完成同一请求。先比较两人的访问状态、额度归属和来源权限。如果所有成员都无法运行，再检查工作区用量、支出限制和服务状态。

记录错误出现时间、统计周期和受影响范围，可帮助管理员判断需要调整的是成员访问、运行设置还是工作区额度。
