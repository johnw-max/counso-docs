# 过滤自动化事件并管理限制

过滤条件决定哪些 Webhook 载荷可以启动助手。限制保护工作区免受高频来源影响，与支付运行费用的额度池是两个概念。

## 开始前

从来源取得一份示例载荷，标出代表有效事件的确切字段和值。再判断触发器服务个人还是整个工作区，使额度池与受益范围一致。

## 编写过滤条件

1. 打开 Webhook 触发器，查看过滤字段。
2. 对受管理来源，如果构建器支持，可以用普通语言描述事件，让它生成过滤条件。
3. 对自定义来源，使用表达式语法。字段路径可写成 `issue.state`，操作符包括 `and`、`or`、`not`、`eq`、`starts-with`、`has`、`has-all`、`has-any`、`gt` 和 `gte`。
4. 用应通过和应忽略的两类事件测试表达式。
5. 保存触发器，观察第一批通过和被拒绝的事件。

例如，下面的表达式只接受状态为 open 且带有 `bug` 标签的 issue：

```text
(and (eq "issue.state" "open") (has "issue.labels" "bug"))

```

## 理解限制和额度

Webhook 触发器在滑动的 24 小时窗口中有单个触发器运行上限。达到上限后到达的请求会被丢弃，不会在窗口恢复后自动重放。周期触发器按自己的计划运行，不使用该 Webhook 上限。

触发器的额度设置可选择 **My credits** 或 **Workspace credits**。团队共享的工作使用工作区额度池，个人简报或报告可以使用成员额度池。所选额度池或支出限制用尽后，运行会停止；错过的运行不会自动重放。

## 完成后应看到什么

触发器只接受匹配的载荷，详情中会显示是否受到频率限制。使用记录会显示所选额度池。若问题来自噪声，先收紧过滤条件，再提高上限。

## 常见问题

### 为什么 Webhook 事件被丢弃？

可能未通过过滤条件、到达时已触及频率上限，或没有可用额度。检查触发器详情和来源载荷。

### 修改额度池会改变过滤条件吗？

不会。额度池控制计费，过滤条件控制哪些事件运行。

### 为什么嵌套字段匹配不上？

检查准确的 JSON 路径、数据类型和数组结构。数组内字段使用通配路径，并在保存前测试真值和假值示例。
