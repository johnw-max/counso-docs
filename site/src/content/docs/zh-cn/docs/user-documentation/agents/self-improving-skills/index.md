# 根据实际使用改进 Skill

应根据真实工作改进 Skill：用户纠正、漏用工具、结果不清楚或反复出现的反馈，比大范围重写更有价值。

## 开始前

收集几段有代表性的对话，并从示例中删除不必要的敏感信息。区分 Skill 本身的问题、助手受众的问题、数据访问问题和外部系统问题。

## 复核并应用改进

1. 打开 Skill Builder，查看近期反馈、纠正和失败或不完整的结果。
2. 如果有改进建议，逐条查看差异，明确它要改变的行为。
3. 只有建议适合目标受众且规则正确时才批准；会扩大访问范围或引入无关流程的建议应拒绝。
4. 手动编辑时，每次只修改一条说明、一个工具或一个知识引用。
5. 用同一代表性请求比较修改前后的结果，同时检查外部写入或文件更新。
6. 保存最小的有效版本，并在 Skill 说明或变更记录中写明改动。

自动改进可以按周期分析对话并为编辑者提出差异。只有编辑者批准后，建议才会修改 Skill。启用前请检查工作区和 Skill 设置，尤其是对话包含机密信息时。

## 完成后应看到什么

Skill 产生新的、可复核的版本，所有使用它的助手都能获得同一流程。改进可以追溯到具体示例，也可以通过历史版本回退。

## 常见问题

### 每次纠正都应变成新规则吗？

不应。只有当纠正代表可重复要求时才加入规则；一次性的偏好保留在对话中。

### 为什么没有出现建议？

建议依赖功能已启用、存在足够可用对话以及工作区处理周期。紧急决定仍应手动复核。

### 自我改进会训练公共模型吗？

它提出的是工作区 Skill 的修改建议。仍应自行复核数据处理、保留和访问设置。
