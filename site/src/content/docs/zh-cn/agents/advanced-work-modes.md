# 选择高级助手工作方式

高级工作方式解决不同的协作问题。可用性取决于工作区、你的角色以及相关助手或 Skill 配置。只有在界面提供相应操作时才使用；管理员可能需要开放能力或授予访问权。请选择能满足任务的最小方式。

## 开始前

写清目标、允许使用的来源、目标位置以及必须由人员复核的节点，再选择方式：

| 需要 | 在可用时使用 |
| --- | --- |
| 不改变原对话，探索另一条路线 | **Branch** 对话分支 |
| 助手运行中需要纠正方向 | **Steering** |
| 交互式创建或改进助手 | **Sidekick** |
| 跨来源研究复杂问题 | **@deep-dive** 或 **Go Deep** |
| 复用经过验证的起点 | **Templates** |
| 将另一个助手作为专门能力运行 | **Run agent** |
| 在不同对话间保留个人偏好 | **Memory** |
| 在未来重复操作或回头检查 | **Wake-ups** |

## 创建分支并引导对话

需要独立工作流、转给另一条工作线或尝试替代方案时使用 Branch。界面提供 Branch 操作后，新对话从选定位置开始，并带有系统生成的摘要；原对话独立继续。分享结果前检查分支中的文件和权限。

当前运行仍有价值但需要新方向时使用 Steering。如果运行中的对话允许发送消息，可以在助手工作期间发送修正；它会完成当前操作，再处理排队的消息。范围、来源或结果要求变化时，用 Steering 代替从头开始。

## 使用 Sidekick 或 Templates 构建助手

1. 如果你的角色和工作区提供该能力，在 Agent Builder 中打开 **Sidekick**，用普通语言描述工作。
2. 以差异形式查看它提出的说明、工具、Skill 和知识改动。
3. 只接受需要的改动，其余手动编辑或拒绝。
4. 从 **Templates** 开始时，把模板当作起点，根据真实流程改写说明再保存。
5. 使用安全样本预览生成的助手。

Sidekick 的建议可复核，不能替代 Builder 的决定。Sidekick 可以帮助配置助手，但 Triggers 和 Skills 仍需分别设置。

## 使用 @deep-dive 或 Go Deep

工作区提供 **@deep-dive** 且任务需要多个来源、数据探索、网页研究或专门子任务时，使用它。管理员开放 **Go Deep** 且允许为自定义助手添加该 Skill 时，再使用 Go Deep。说明范围、来源、排除项和交付物。分享前阅读引用证据，并复核生成的文件或 Frame。

## 将助手作为能力运行

助手已配置 Run agent 能力，且需要专门助手完成隔离子任务并返回结果时，使用 **Run agent**。给它自包含的任务说明、允许使用的数据和明确的返回形式。适合独立研究或可复用的专门行为；主助手仍负责组合和检查结果。

## 使用 Memory 和 Wake-ups

助手构建器提供并启用 **Memory** 能力，且助手需要在不同对话间保留个人偏好或连续性时使用它。可以明确要求它记住某个偏好；相关控件可用时，从助手详情中查看或删除记忆。Memory 属于个人，不应当作共享 Pod 记录。

工作区提供 Wake-up 能力，且助手需要未来执行、等待回复或刷新 Pod 产物时使用 **Wake-up**。要求助手带理由和频率创建唤醒任务，并检查目标、负责人和重复次数；不再需要时在创建它的对话中取消。Wake-up 使用发起用户的权限。

## 完成后应看到什么

启用并使用某种方式后，创建分支时原对话仍可用，运行中的助手会处理 Steering 消息，Agent Builder 会显示已接受的配置变化。深度调查返回研究结果，子助手返回限定结果，Memory 出现在助手的记忆区域，Wake-up 出现在待执行的未来操作中。

## 常见问题

### 可复用流程应该用 Skill 还是 Run agent？

多个助手需要共享说明和工具时使用 Skill。工作需要独立对话和隔离调查时使用 Run agent。

### 深度调查后 Frame 会自动保持最新吗？

生成的 Frame 是快照，需要重新生成或覆盖。配置的数据读取视图可以在打开或使用 **Refresh** 时反映已保存的 Pod 记录和 Tasks；关闭后不会执行任务。

### 其他人能修改我的 Wake-up 吗？

Wake-up 使用发起用户的权限。请在创建它的对话中查看和取消。
